# 독립된 백그라운드 수집

결정:

- 서버는 저장소 준비 후 크롤링 완료를 기다리지 않고 응답한다. 채용과 뉴스는 각각 시작 시 1회 및 사용자의 수동 요청으로 수집한다. 반복 스케줄·알림·별도 작업 큐는 두지 않는다.
- 두 관리자의 실행 가드와 진행 상태는 독립적이다. 같은 관리자의 중복 실행은 거절하고, 채용과 뉴스는 동시에 실행할 수 있다. 종료 시 두 작업을 정리한다.
- 채용은 Async Playwright Chromium 하나와 카테고리별 페이지를 사용한다. 동시 작업 수 `1/2/4`를 웹에서 선택해 SQLite에 저장하며 기본값은 `2`다.
- 한 카테고리·출처의 실패가 다른 수집이나 웹서버를 중단시키지 않는다. 채용은 전체 종료 후 성공 결과를 저장하고 실패 카테고리를 재시도할 수 있다. 뉴스는 완료된 출처별로 저장하고 전체 수동 수집으로 재시도한다.
- 채용과 뉴스의 domain·repository·manager 및 뉴스 출처별 파서는 각자의 책임을 유지한다. 범용 크롤러 엔진으로 합치지 않는다.

이유: 수집 중에도 기존 목록과 사용자 상태를 즉시 사용할 수 있고, 일부 출처의 장애가 앱 전체로 번지지 않게 하기 위해서다.
