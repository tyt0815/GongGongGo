# GongGongGo 뉴스·기관소식 Inbox 확장 설계

작성일: 2026-08-25  
상태: 사용자 승인 완료, 구현 전

## 1. 목적

GongGongGo에 취업 준비용 `뉴스/기관소식` Inbox를 추가한다. 사용자는 한국경제와 매일경제의 주요 분야 기사, 관심 공공기관 세 곳의 보도자료를 한 화면에서 빠르게 훑고 원문을 연 뒤 처리 완료할 수 있다.

이 기능은 장기 뉴스 아카이브가 아니다. 본문, 첨부파일, 요약, 추천, 북마크나 복잡한 읽음 상태를 저장하지 않는다. 가치 있는 자료는 사용자가 직접 Obsidian에 정리한다. GongGongGo에는 제목, 링크, 출처, 분류, 게시일시와 최초 수집시각만 짧게 보관한다.

기존 채용공고 기능과 데이터 모델은 변경하지 않는다. 뉴스 기능은 별도 domain, crawler, manager, repository와 테이블로 구현한다.

## 2. 범위

### 포함

- 기존 대시보드의 최상위 `채용공고 | 뉴스/기관소식` 전환
- 한국경제와 매일경제 원본 사이트의 주요뉴스·정치·경제·사회·IT·세계 목록 수집
- 한국부동산원·신용보증기금·한국가스공사 공식 보도자료 목록 수집
- 제목, 정규화 URL, 출처, 통합·원본 분류, 게시일시, 최초 수집시각 저장
- 신문 7일, 기관 보도자료 30일 보관
- 오늘·어제·최근 3일·최근 7일·최근 30일 조회
- 자료 종류·출처·분류 필터와 제목 부분 검색
- 원문 새 탭 열기와 처리 완료
- 처리 완료 항목의 TTL 경계까지 임시 재수집 억제
- 시작 시 백그라운드 1회 수집과 뉴스 화면의 수동 수집
- 출처별 진행 상태, 부분 실패와 기존 날짜별 로그 연동

### 제외

- 기사·보도자료 본문과 첨부파일 저장
- AI 요약·분류·추천·중요도 평가
- Obsidian 연동
- 읽음·안 읽음·북마크·보관 등 추가 상태
- 영구 뉴스 차단 목록
- 반복 scheduler, 알림, 계정, 외부 배포
- React·Vue 등 신규 프런트엔드 프레임워크
- 최초 실행 시 신문 최근 7일 전체 역수집

## 3. 수집원과 접근 정책

다음 공식 목록을 사용한다.

- 한국경제: `https://www.hankyung.com/all-news`와 동일 사이트의 분야별 전체뉴스 목록
- 매일경제: `https://www.mk.co.kr/news/`와 동일 사이트의 분야별 뉴스 목록
- 한국부동산원: `https://www.reb.or.kr/reb/na/ntt/selectNttList.do?mi=9565&bbsId=1154`
- 신용보증기금: `https://www.kodit.or.kr/kodit/na/ntt/selectNttList.do?mi=2639&bbsId=47`
- 한국가스공사: `https://www.kogas.or.kr/site/koGas/goBoard.do?boardNo=41&Key=1010202000000`

네이버 언론사 홈은 두 신문에 동일한 파서를 적용하기 쉽지만, `media.naver.com/robots.txt`가 일반 봇의 전체 경로 접근을 금지하므로 수집원으로 사용하지 않는다. 신문 원본 사이트는 2026-08-25 확인 기준 사용할 목록 경로를 일반 크롤러에 허용한다.

목록 페이지가 정적 HTML로 제목·링크·게시일시를 제공하므로 HTTP 요청과 BeautifulSoup을 우선한다. Playwright는 뉴스 수집에 사용하지 않는다. 요청은 식별 가능한 GongGongGo User-Agent, timeout과 기존 로깅을 사용하며 높은 빈도의 반복 요청을 하지 않는다. 단, 매일경제 목록에 게시일시가 없는 항목은 현재 최신 목록 전체를 포괄하는 안전 상한인 실행당 최대 100개의 공식 기사 페이지를 요청해 `article:published_time` 또는 JSON-LD `datePublished` 메타데이터만 확인한다. 본문은 파싱하거나 저장하지 않으며 개별 상세 요청 실패는 해당 항목의 최초 수집일 fallback으로 격리한다. 네이버뉴스와 기사 URL 숫자를 통한 날짜 추측은 사용하지 않는다.

## 4. 아키텍처와 모듈 경계

새 기능은 `src/news/` 패키지에 둔다.

- `domain.py`: 뉴스 항목, 출처 결과, 실행 snapshot 모델
- `repository.py`: 뉴스 항목, 임시 억제 기록과 조회 전용 저장소
- `manager.py`: 뉴스 실행 가드, 진행 상태, 출처별 부분 실패와 저장 조정
- `http.py`: HTTP fetch, timeout, User-Agent와 응답 검증
- `url_normalization.py`: URL 정규화
- `classification.py`: 한국부동산원 정기 통계 제목 분류
- `sources/hankyung.py`, `sources/mk.py`, `sources/reb.py`, `sources/kodit.py`, `sources/kogas.py`: 출처별 목록·날짜·링크 파싱과 페이지 이동

출처 모듈은 같은 작은 호출 계약을 따르지만 DOM selector와 페이지 이동 규칙은 공유하지 않는다. 새 출처는 기존 파서를 수정하지 않고 source registry와 새 모듈을 추가해 확장한다. 설정 기반 범용 selector 엔진은 만들지 않는다.

기존 `Repository`, `CrawlManager`, `CrawledPost`, `crawler.py`는 채용공고 전용 구조로 유지한다. 기존 `app.state.manager`와 채용 API도 그대로 둔다. 중앙 연결부에는 다음 변경만 한다.

- `database.py`에서 뉴스 스키마 초기화 호출
- `web.py`에서 `NewsRepository`와 `NewsCrawlManager` 생성 및 뉴스 API 등록
- lifespan에서 서버 응답을 기다리지 않고 채용·뉴스 시작 작업을 각각 예약하고, 종료 시 둘 다 정리

UI는 기존 `static/app.js`의 채용 동작을 재작성하지 않는다. `templates/index.html`에는 최상위 전환과 뉴스 영역을 추가하고, 뉴스 동작과 스타일은 `static/news.js`, `static/news.css`로 분리한다.

## 5. 데이터 모델

기존 SQLite 파일에 다음 독립 테이블을 추가한다.

### `news_items`

- `id`: 기본키
- `item_type`: `newspaper` 또는 `institution`
- `source`: `hankyung`, `mk`, `reb`, `kodit`, `kogas` 등 내부 식별자
- `source_name`: 한국어 표시명
- `category`: 내부 통합 분류
- `source_category`: 원본 분류가 다를 때 저장하는 nullable 값
- `title`
- `url`: 정규화된 URL, `UNIQUE`
- `published_at`: 게시일 또는 게시시각, 없으면 `NULL`
- `discovered_at`: 최초 수집시각

`item_type`에는 안정된 두 값의 `CHECK`를 둔다. `source`는 새 출처 추가 때 DB migration을 요구하지 않도록 고정 목록 `CHECK`를 두지 않고 애플리케이션 registry에서 검증한다.

### `news_dismissals`

- `url`: 정규화된 URL, 기본키
- `dismissed_at`
- `expires_at`

처리 완료는 한 번의 짧은 트랜잭션에서 `news_items` 행을 삭제하고 `news_dismissals`를 upsert한다. 억제 만료는 항목의 원래 TTL 경계로 계산한다. 게시 후 5일째인 신문 기사를 처리하면 약 2일 뒤 억제 기록도 제거된다. 게시일이 없으면 최초 수집일을 기준으로 한다.

크롤러는 활성 억제 URL을 삽입하지 않는다. 억제 기간이 끝난 URL은 이후 목록에 다시 등장할 경우 신규 항목으로 수집할 수 있다.

## 6. URL 정규화와 중복

URL은 다음 범위만 보수적으로 정규화한다.

- scheme과 host 표준화
- fragment 제거
- 기본 포트와 불필요한 trailing slash 정리
- `utm_*` 등 명백한 추적 파라미터 제거

기관 게시물 ID와 같이 페이지 식별에 필요한 query parameter는 보존한다. 제목 유사도나 본문 기반 중복 판정은 하지 않는다.

같은 신문 기사가 여러 목록에 나타나면 URL 고유 제약으로 한 행만 저장한다. 분야별 목록을 먼저 처리하고 `주요뉴스`를 마지막에 처리해 `주요뉴스`가 더 구체적인 분류를 덮지 않게 한다. 드물게 여러 구체 분야에 동시에 나타나면 설정된 분야 처리 순서에서 먼저 얻은 분류를 유지한다.

## 7. 분류

신문사별 원래 명칭은 다음 내부 범주로 통일한다.

- 주요뉴스
- 정치
- 경제
- 사회
- IT
- 세계

생활, 연예, 스포츠, 영상, 클립, 사설·칼럼, 랭킹과 신문보기는 수집하지 않는다.

기관 자료는 기본적으로 `보도자료`다. 한국부동산원 제목이 다음과 같이 명백한 정기 조사·동향 패턴과 일치할 때만 `정기 통계`로 분류한다.

- 주간아파트가격동향
- 전국주택가격동향
- 상업용부동산 임대동향

규칙은 대소문자와 불필요한 공백을 정규화한 제목 부분 일치의 순수 함수로 구현한다. 애매한 제목은 추론하지 않고 `보도자료`로 둔다.

## 8. 수집 범위와 데이터 흐름

뉴스 관리자는 기존 채용 관리자와 별도 `asyncio.Task`를 가진다. 중복 뉴스 실행만 거절하며 채용 수집과 동시에 실행할 수 있다.

실행 순서는 다음과 같다.

1. 만료된 뉴스와 억제 기록 정리
2. 다섯 출처 작업을 서로 독립적으로 시작
3. 출처 하나 안에서는 목록 페이지를 순차 요청
4. 완료되는 출처마다 성공 결과를 짧은 DB 트랜잭션으로 반영
5. 출처별 성공·실패와 전체 snapshot 갱신
6. UI가 완료를 감지하면 뉴스 목록 갱신

신문은 첫 실행을 포함해 여섯 범주의 최신 목록 페이지만 수집한다. 처음부터 최근 7일 전체를 역수집하지 않는다. 이후 시작·수동 수집 결과가 누적되며 TTL 안에서 최대 7일치 Inbox가 형성된다. 매일경제는 목록 수집을 모두 마친 뒤 같은 URL의 목록 날짜를 우선 재사용하고, 여전히 게시일시가 없는 고유 URL만 공식 기사 메타데이터로 보강한다.

기관은 첫 실행부터 게시일 기준 최근 30일 경계에 도달할 때까지 페이지를 이동한다. 이후 실행도 같은 경계에서 멈춘다. DOM 변경이나 날짜 오류로 무한 요청하지 않도록 출처별 최대 10페이지 제한을 둔다.

서버 lifespan은 기존 저장소를 준비한 뒤 채용과 뉴스 시작 작업을 각각 예약하지만 완료를 기다리지 않는다. 종료 시에는 두 작업을 모두 안전하게 기다린다. 반복 scheduler와 자동 고빈도 요청은 없다.

## 9. 날짜와 보관 정책

날짜 판정은 `Asia/Seoul` 달력 날짜를 기준으로 한다.

- 신문은 유효 게시일 기준 오늘을 포함한 최근 7일만 유지
- 기관은 유효 게시일 기준 오늘을 포함한 최근 30일만 유지
- 게시일시를 파싱하지 못했거나 목록에 없으면 최초 수집일을 대신 사용
- 오늘·어제·최근 N일 필터도 같은 유효 날짜와 한국 시간 경계를 사용

DB 초기화와 뉴스 수집 시작 시 cleanup을 실행한다. 별도 scheduler는 추가하지 않는다. 신문과 기관의 만료 항목을 삭제하고 `expires_at`이 지난 억제 기록도 제거한다.

## 10. 진행 상태와 오류 처리

뉴스 snapshot은 다음 값을 제공한다.

- 실행 중 여부
- 전체·완료 출처 수
- 신규 저장 수
- URL 중복 수
- TTL 삭제 수
- 출처별 간결한 오류
- 전체 실행 오류

오류 단위는 다음과 같다.

- malformed 항목 하나: 해당 항목만 건너뛰고 경고 로그
- 예상 목록 구조 누락: 해당 출처 실패
- timeout 또는 HTTP 오류: 해당 출처 실패
- DB 저장 실패: 해당 출처 저장 실패로 표시하고 다른 출처 계속
- 관리자 자체 오류: 전체 오류로 표시하되 웹서버와 채용 관리자 유지

자동 반복 재시도는 하지 않는다. 사용자는 뉴스 화면의 전체 수집 버튼으로 다시 실행한다. 상세 예외와 traceback은 기존 날짜별 파일 로그에 기록하고 UI에는 간결한 출처별 오류만 표시한다.

로그에는 실행 시작·종료, 출처별 시작·성공·실패, 수집·신규·중복·TTL 삭제 수와 selector·파싱 오류를 남긴다. 정상 항목 하나마다 INFO 로그를 남기지 않는다.

## 11. API

기존 API는 변경하지 않고 다음 경로를 추가한다.

- `GET /api/news`
- `DELETE /api/news/{id}`
- `POST /api/news/crawl/start`
- `GET /api/news/crawl/status`

목록 API는 다음 query를 검증한다.

- 기간: `today`, `yesterday`, `3d`, `7d`, `30d`; 기본 `today`
- 자료 종류: 전체, `newspaper`, `institution`
- 출처: 전체 또는 source registry의 식별자
- 분류: 전체 또는 지원 분류

화면의 출처·분류 복수 체크는 기간·자료 종류·검색 조건으로 조회한 결과에 클라이언트 필터로 적용한다. 따라서 기존 단일 값 API 계약은 유지한다.
- 제목 검색어: 단순 부분 일치

`DELETE /api/news/{id}`는 처리 완료 의미다. 성공하면 항목 삭제와 임시 억제를 함께 수행하며, 없는 항목은 404를 반환한다. DB 오류는 기존 API와 같은 방식으로 로그를 남기고 503으로 변환한다.

수동 시작은 뉴스 실행 중이면 409를 반환한다. 뉴스 실행 여부는 채용 수동 시작의 허용 여부에 영향을 주지 않는다.

## 12. UI/UX

기존 페이지 상단에 `채용공고 | 뉴스/기관소식` 최상위 전환을 둔다. 페이지를 새로 열면 기존처럼 채용공고가 기본 화면이다. 기존 채용 DOM과 동작은 가능한 그대로 보존하고 뉴스 화면은 처음 선택할 때 API로 데이터를 읽는다.

뉴스 화면 상단에는 다음을 둔다.

- `오늘`, `어제`, `최근 3일`, `최근 7일`, `최근 30일` 기간 선택
- 전체·뉴스·기관소식 버튼으로 구성한 자료 종류 필터(페이지를 열 때 전체가 기본)
- 복수 선택 체크박스로 구성한 출처·분류 필터(최초에는 모두 선택하고 마지막 체크 상태를 브라우저 `localStorage`에 보존)

필터는 자료 종류, 기간, 출처, 분류, 제목 검색 순서로 한 줄씩 쌓는다. 자료 종류·출처·분류의 화면용 소제목은 두지 않고 접근성 이름만 유지한다. 목록 위에는 현재 필터 조합으로 실제 표시되는 항목 수를 `총 N건`으로 표시하고 필터 변경과 처리 완료 시 즉시 갱신한다.
- 제목 검색
- 뉴스 전용 `새로 수집` 버튼
- 뉴스 수집 진행률과 출처별 오류

목록은 화려한 카드 대신 최신 게시일순의 밀도 높은 한 열 목록으로 표시한다.

신문 행은 출처, 통합 카테고리와 게시시각을 먼저 보여준다. 기관 행은 기관명, `보도자료` 또는 `정기 통계`, 게시일을 보여준다. 게시일이 없어 최초 수집일을 사용하면 `수집일 기준`을 작게 표시한다.

제목은 저장 URL을 새 탭으로 연다. 별도의 중복 `원문 보기` 링크는 표시하지 않는다. 링크를 여는 동작은 읽음이나 처리 완료로 간주하지 않는다. `처리 완료` 성공 후 해당 행을 즉시 제거하고, 실패하면 행을 유지한 채 오류를 표시한다. 확인창, undo와 추가 상태는 만들지 않는다.

데스크톱은 메타정보·제목·동작을 밀도 있게 배치한다. 모바일은 제목과 버튼을 두세 줄로 재배치해 가로 overflow 없이 사용할 수 있게 한다. 채용 설정 drawer에는 뉴스 설정을 추가하지 않는다.

## 13. 테스트

구현 전 현재 전체 테스트를 실행해 기준 상태를 기록한다. 뉴스 기능은 테스트 우선으로 구현한다.

### 단위 테스트

- 다섯 출처의 실제 구조에서 축소한 최소 HTML fixture 파싱
- 정상·빈 목록, malformed 항목, 예상 목록 구조 누락
- URL 추적 파라미터 제거와 의미 있는 ID query 보존
- 구체 분류 우선의 URL 중복 처리
- 한국부동산원 정기 통계 제목 분류
- 날짜 파싱 실패 시 최초 수집일 fallback
- 매일경제 공식 기사 `article:published_time`·JSON-LD 날짜 파싱과 상세 요청 실패 격리

### 저장소 테스트

- 기존 데이터가 있는 DB의 무손실 뉴스 스키마 추가
- URL 고유 제약과 신규·중복 수 집계
- 신문 7일·기관 30일 cleanup
- 처리 완료의 원자적 삭제·임시 억제
- 억제 만료 후 재수집 허용
- 기간·종류·출처·분류·검색 조합

### 관리자와 API 테스트

- 뉴스 중복 실행 거절과 채용 실행 상태 독립
- 한 출처 실패 시 다른 출처 결과 저장
- 출처·전체 오류와 진행 snapshot
- 목록 query 검증, 처리 완료 404와 DB 오류
- 서버가 두 크롤링 완료 전에 응답

### UI와 회귀 테스트

- 최상위 화면 전환과 기존 채용 기본 화면
- 기간·자료 종류 버튼·출처/분류 복수 체크·검색
- 출처/분류 마지막 체크 상태 복원과 자료 종류 전체 기본값
- 제목 원문 새 탭과 처리 완료
- 데스크톱 밀도형 목록과 모바일 재배치
- 기존 채용 API·설정·상태 변경·영구 삭제·대시보드 E2E 계약

자동 테스트는 외부 사이트를 호출하지 않는다. 파서는 실제 페이지에서 필요한 구조만 축소한 UTF-8 fixture로 검증한다. 실제 네트워크는 selector 확인과 마지막 제한된 smoke에만 사용하며 운영 DB 대신 임시 DB를 사용한다.

## 14. 완료 기준

- 기존 테스트와 신규 테스트 전체 통과
- `git diff --check` 통과
- 임시 DB를 사용하는 실제 FastAPI 시작 경로에서 서버가 두 크롤링을 기다리지 않고 응답
- 뉴스 수동 수집·필터·처리 완료·부분 실패 상태 확인
- 다섯 공식 목록에서 현재 selector smoke 성공
- 기존 채용 상태와 운영 DB 데이터가 변경되지 않음
- 구현된 동작에 맞춰 README와 `docs/HANDOFF.md` 갱신

## 15. 구현하지 않는 확장

현재 설계는 개인용 임시 Inbox라는 목적에 필요한 최소 구조만 포함한다. 새 신문사, 설정 가능한 출처·TTL, 범용 scraper engine, 영구 실행 이력, 출처별 재시도 버튼, 뉴스 통계와 자동 Obsidian 연동은 실제 필요가 생길 때 별도 설계한다.
