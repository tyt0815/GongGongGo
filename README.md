# GongGongGo

공공기관 채용 공고를 수집하고 검토 상태를 관리하는 로컬 전용 웹앱입니다.

## 현재 상태

현재 코드는 FastAPI, Jinja2, Playwright와 JSON 파일을 사용합니다. 앱을 실행하면 크롤링을 먼저 마친 뒤 `127.0.0.1:8000`에서 웹서버를 시작합니다. 웹 화면에서는 공고를 `대기`, `지원 예정`, `완료`로 분류할 수 있습니다.

2026-08-03에 전체 개선 설계가 승인되었지만 아직 구현되지는 않았습니다. 다음 단계는 승인된 설계를 바탕으로 상세 구현 계획을 작성하는 것입니다.

- [승인된 개선 설계](docs/superpowers/specs/2026-08-03-gonggonggo-modernization-design.md)
- [다음 세션 인수인계](docs/HANDOFF.md)

## 현재 실행 방법

프로젝트 가상환경과 Playwright Chromium이 준비되어 있다는 전제에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe main.py
```

크롤링이 끝난 뒤 브라우저에서 `http://127.0.0.1:8000`에 접속합니다. 현재 저장소에는 의존성 선언 파일이 없으므로 재현 가능한 설치 절차는 개선 작업에서 추가해야 합니다.

Windows 시작 스크립트는 `ggg_startup.bat`과 `ggg_startup.vbs`입니다. 현재 동작과 승인된 숨김·디버그 실행 구조의 차이는 인수인계 문서에 정리되어 있습니다.

## 승인된 개선 방향

- 웹서버를 즉시 열고 크롤링은 백그라운드에서 실행
- Async Playwright로 카테고리 동시 작업 수 `1/2/4` 지원
- JSON에서 SQLite로 이전하고 사용자 상태와 크롤러 갱신의 충돌 방지
- QHD에서는 두 상태 목록을 나란히, 좁은 창에서는 하나의 상태 탭만 표시
- 기관·고용 형태·경력·직무를 파싱해 공고를 읽기 쉽게 표현
- 기관 및 IT 직무 키워드를 웹 설정에서 편집
- 날짜별 로그를 저장하고 14일이 지난 로그를 시작 시 정리
- 작업 스케줄러용 숨김 실행과 문제 확인용 콘솔 실행 분리

## 현재 데이터

`data/job_posts.json`은 현재 운영 데이터이며 개선 구현 전까지 원본을 보존해야 합니다. 승인된 마이그레이션은 정상 날짜 공고만 SQLite로 가져오고, 날짜를 파싱할 수 없는 기존 공고는 건너뜁니다.
